# OPPO 面试简历描述与 PPT 思路包装

## 📄 简历项目经历 (复制即用)

**项目名称**：基于大模型赋能与端云协同的轻量级多任务推荐系统 (个人独立项目)
**核心技术**：LLM (Moonshot/Qwen), PyTorch, MMoE, ONNX Runtime, FastAPI
**项目背景**：针对传统推荐系统（如应用商店分发）中长尾物料冷启动困难、云端排序延迟高且难以利用端侧实时隐私特征的痛点，设计并实现了一套“云端 LLM 特征增强 + 端侧轻量重排”的端云协同分发架构。

**主要工作与业绩**：
1. **[LLM 赋能冷启动]** 创新性地引入大模型（Kimi/Qwen）强大的 Zero-shot 语义理解能力，对应用描述进行离线信息抽取（类别、核心卖点、适用场景），将其转化为结构化意图标签，显著缓解了新物料冷启动时的特征稀疏问题。
2. **[云端多任务精排]** 在云侧基于 PyTorch 构建了轻量级的 MMoE (Multi-gate Mixture-of-Experts) 模型，同时对 CTR（点击率）和 CVR（下载转化率）进行联合预估，有效捕捉了不同转化节点的数据分布差异。
3. **[端侧实时重排与隐私保护]** 针对 OPPO 手机端侧算力丰富的特点，设计了“端云协同”范式：云端下发 Top-N 候选集与基础 Logits；在端侧，利用 **ONNX Runtime** 部署极轻量级的重排网络 (Edge Re-ranker)，融合仅在本地计算的隐私特征（如实时电量、极短期点击流），在毫秒级内输出最终展示列表。
4. **[工程落地与性能优化]** 独立完成端到端全链路搭建，使用 FastAPI 提供云端服务接口。利用 PyTorch `torch.onnx.export` (Opset 17) 将重排模型转为 ONNX 格式，在本地 CPU 端模拟实现了极低延迟的实时推理。

## 📊 PPT 答辩汇报思路 (结构大纲)

如果在 OPPO 面试时要求你做一个 10 分钟的项目汇报（或你在口述时），请遵循以下逻辑结构：

### 1. 痛点分析 (Why I did this?)
- **业务场景**：OPPO 软件商店 / 负一屏信息流。
- **痛点一**：传统双塔/排序模型极其依赖 ID 类特征的历史共现，新上架的 App (冷启动) 根本分发不出去。
- **痛点二**：用户的实时状态（比如手机快没电了、现在处于无WIFI状态）对转化率影响极大，但这些特征高度隐私且瞬息万变，不适合实时上传云端。

### 2. 架构创新 (The "Cloud-Edge" Solution)
- **展示你的架构图**（你可以用我们写的代码生成流程图）：
  - `Cloud`: LLM Tagging -> MMoE Scoring -> Top-K 候选集下发。
  - `Edge`: 接收 Top-K -> 捕获本地特征 (电量/网络/点击流) -> ONNX 轻量重排 -> 最终展现。

### 3. 技术深挖 (Show your coding skills)
- **亮点 1: 大模型“降维打击”**。展示你的 `llm_feature_extractor.py` 逻辑，告诉面试官：“我没有花几万块钱去从头训练一个大模型，而是巧妙利用了现有 API，用 Prompt 规范输出 JSON 结构化标签，这在工程上极具性价比”。
- **亮点 2: 为什么用 MMoE？**。不要只说“因为它流行”。要说：“在应用分发场景，点击(CTR)和下载(CVR)既有联系又有冲突。MMoE 通过多个门控网络(Gates)让不同的 Task 自由组合 Expert 的权重，缓解了多任务学习中的‘跷跷板效应’”。
- **亮点 3: 端侧部署 ONNX**。展示你的 `edge_onnx_export.py` 成果。强调：“我没有用笨重的 PyTorch 跑端侧，而是导出了静态图的 ONNX 模型，并使用 CPUExecutionProvider，这证明我懂工业界的部署规范”。

### 4. 未来展望 (Show your business vision)
- 如果我入职 OPPO，我会怎么改进这个项目？
  - 端侧：引入联邦学习 (Federated Learning)，让端侧的小模型能不断进化，且保护隐私。
  - 排序：将 MMoE 升级为 PLE (Progressive Layered Extraction)，进一步优化任务间的特征隔离。
